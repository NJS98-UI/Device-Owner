## 0. 调用形状

原车用的不是裸 `VDBus.set()`，而是 SDK 包装：

```java
CarInfoProxy.getInstance().sendItemValue(int eventId, int cmdId, int value)   // 写
CarInfoProxy.getInstance().getItemValue(int eventId, int cmdId)               // 读
CarInfoProxy.getInstance().getItemValues(int eventId, int cmdId)              // 读，返回 int[]
CarInfoHelper.setDelayTimerCount(eventId, cmdId, 10)                          // 写完 10×?ms 内抑制回读抖动
```

落到我们已验证的反射路径上就是：`VDBus.set(VDEvent(eventId, Bundle{CMD_ID:cmdId, VALUE:value}))`。
写入后必须 get 回读校验（这条已在实机证明可用，普通应用 uid 10018 即可）。

两个 eventId（都是 serviceType = CAR_INFO）：

| eventId | 十六进制 | 内容 |
| --- | --- | --- |
| 327690 | 0x5000A | 空调（HVAC）全部开关/温度/风量/除霜/循环 |
| 327681 | 0x50001 | 座椅加热通风按摩、方向盘加热、仪表显示模式（232） |

### 200/211/237/238 的取值（`SeatWheelFragment` 的档位数组 + 实机抓取完全吻合）

| 值 | 含义 |
| --- | --- |
| 1 | 关（加热、通风都关） |
| 10 / 6 / 2 | 加热 1档 / 2档 / 3档 |
| 25 / 21 / 17 | 通风 1档 / 2档 / 3档 |

```java
// SVHvac 原车代码等价逻辑
private int getSeatHeatGearByArrayIndex(int level) {      // 加热
    switch (level) { case 1: return 10; case 2: return 6; case 3: return 2; default: return 1; }
}
private int getSeatVenlationGearByArrayIndex(int level) {  // 通风
    switch (level) { case 1: return 25; case 2: return 21; case 3: return 17; default: return 1; }
}
```

原车 `MAX_SEAT_VALUE = 25`；`getFontLeftSeatState()` 读回 200 后 `value > 25` 一律当 0（非法值丢弃）。

### 后排在位状态（139/141/142/144）

独立通道，取值就是 0..3（`const/4 v1, #int 3` 做上限校验）：0=关，1/2/3=档。
主副驾没有这种简单通道，只能走 200/211 的编码值。
