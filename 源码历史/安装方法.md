# 仪表投屏（系统手势广播版）

适用：捷途 T1J（jetour_t1j / 德赛西威 DesaySV / Chery-8155 / Android 11）车机。
当前版本：**v4.1.4（versionCode 25）**，Kotlin 源码在 `v4.1.3\src\`；
上一版 v3.2.2（versionCode 12）的 Java 源码就是本文件同级的那份，保留作对照。

**这一版保证的事**
1. **运行期不需要 root、不需要 Shizuku、也不需要无障碍**。装 APK 也不需要 root（见第三节）。
2. **不碰原车高德**。仪表模式走德赛私有总线，不再拿高德的投屏通道当退出兜底，
   所以原车高德主屏照开、它自己的三指投屏照常。
3. **点应用就是点应用**。主屏点任何应用都不会自动改仪表屏，仪表屏只在你真做三指滑动时才动。

## 一、真机取证结论

以下都是在你的车机上用 adb + 反编译系统包实测出来的，不是推测。
完整原始数据在同目录的 `仪表投屏-交付-20260919/抓包数据/`，逐条对应关系见
`仪表投屏-交付-20260919/协议说明.md`。

### 1. 三指手势是系统识别的，而且公开广播

`/system/framework/dsv-system-gesture.jar` → `com.android.server.wm.CarSystemGesturesManager`
（跑在 system_server 里）识别多指手势后：

```java
i.setAction("android.intent.action.car_system_gesture_mode");
i.putExtra("gesture", gesture);          // int = 手指数×100 + 方向（0左 1右 2下 3上 4捏合）
i.putExtra("display", displayId);        // int
mContext.sendBroadcastAsUser(i, UserHandle.ALL);   // ← 没有 receiverPermission
```

所以 300=三指左滑、301=三指右滑，任何普通应用 `registerReceiver` 就能收到。这是免 root 的入口。

注意：该 action 受保护，`adb shell am broadcast` 会被拒（`SecurityException`），只有真手指能触发。

### 2. display 2 不是私有屏

`/vendor/etc/dsv_multi_display_config.xml` 里 `Display_CLUSTER` 的 id 就是 2，
flag 只有 `FLAG_PRESENTATION | FLAG_TRUSTED`，**没有 FLAG_PRIVATE**，
所以 `ActivityOptions.setLaunchDisplayId(2)` 零权限可用。

（display 5 是 `com.desaysv.launcher` 的私有虚拟屏，用于主屏内嵌小窗，跟仪表投屏无关。）

### 3. 仪表模式只能走德赛 VDBus

`/system/framework/vdbus.jar`，service=CAR_INFO，eventId=327681，
请求 Bundle `putInt("CMD_ID", 232)`，返回 `getIntArray("VALUE")`。

| 协议值 | 仪表模式 |
|---|---|
| 1 | 数字模式 |
| 2 | 经典模式 |
| 3 | 导航模式 |
| 4 | 极简模式 |

仪表模式**不在** Settings、**不在** prop、也不是广播（切模式前后做过全量 diff，只有
`com.desaysv.status.bar.status` 变），所以只能走总线。
服务端 `CarInfoService.onSet` 不校验 uid，理论上普通应用可读写。

### 4. 桌面音乐卡片显示不了自装音乐，是白名单问题不是权限问题

桌面卡 `T1hMediaCard` 读 VDBus MEDIA 服务的 `393218 / VDMediaInfo`，
而 `VDValueMedia$MediaType` 枚举里**根本没有酷狗这一档**，所以只能显示"未知频道"。
对策：自己 new 一个 `VDMediaInfo`（mediaType 填 ONLINE_MUSIC=14）推上总线，代码在 `Vd.publishMedia()`。

### 5. 读"正在放什么歌"要跳过空会话

车机上 `com.bytedance.byteautoservice3` 常驻上报 `STATE_PLAYING` 但 `metadata: null`，
按播放状态先挑会选中它、把真正在放歌的酷狗挤掉。`MusicListener.active()` 已改成
只在带歌名的会话里挑。

## 二、v3.2 的行为

| 操作 | 结果 |
|---|---|
| 主屏点任意应用 | 只在主屏打开，**绝不自动投屏** |
| **三指左滑** | 先把仪表切到原车「极简模式」，再把画面放到仪表屏 |
| **三指右滑** | 收掉我们的页面，仪表**退回进投屏前那个模式**（回读确认） |
| 勾「极简模式」 | 仪表屏只放我们自己的播放信息页，音乐 App 那份实例留在主屏照常点（推荐） |
| 不勾「极简模式」 | 整屏投应用：把目标/前台应用直接启到 display 2 |
| 勾「三指左滑自动投当前前台应用」 | 谁在前台投谁，最接近原车手感（需一次性授权"使用情况"） |
| 勾「对接桌面音乐卡片」 | 把自装音乐的歌名/歌手推上总线，原车桌面那张卡也能显示 |
| 原车高德 | 完全不动，主屏照开，它自己的三指投屏照常 |

界面上方状态行会显示当前仪表模式（数字/经典/导航/极简），日志区显示每次动作的实际结果。

两个实现细节：

- **切模式后一定回读**。总线那层 `VDBus.set()` 返回 void，"没抛异常"不等于切过去了。
  现在写完 sleep 250ms 再 `getTheme()`，日志按回读结果写，没生效会直说"还停在导航模式"。
- **极简页而不是搬应用**。singleTask 应用（酷狗、腾讯地图）没法在主屏和仪表屏同时存在两份实例，
  搬过去主屏就打不开；放我们自己的页面就没这个问题。

## 三、安装

### 前提
车机已开 ADB 调试，`adb devices` 能看到设备。

### 第 1 步：装 APK（走 MT 管理器，不需要 root）

这台 ROM 拦住了 adb 安装：`adb install` 会报
`SecurityException: Restriction prevents installing`（`PackageManagerShellCommand.doCreateSession`）。
ROM 只拦 adb/shell 这条路径，正常安装器不拦，所以推文件后用 MT 管理器拉起安装界面：

```powershell
adb push 源码\v4.1.3\ClusterCast-v4.1.4.apk /sdcard/Download/
adb shell am start -n bin.mt.plus/.OpenFileActivity -d file:///sdcard/Download/ClusterCast-v4.1.4.apk -t application/vnd.android.package-archive
```

车机上弹的安装框点"安装"。没有 MT 管理器就用 U 盘拷进去、车机文件管理器点开装，效果一样。
构建脚本 `v4.1.3\build.ps1 -Install` 会自动跑这两步。

```powershell
adb shell am start -n com.ahui.clustercast/.MainActivity
```

### 第 2 步：授权通知使用权（读歌名用，重启不失效）

这台 ROM 也没有通知使用权的设置页，只能命令行授权一次：

```powershell
adb shell cmd notification allow_listener com.ahui.clustercast/.MusicListener
```

不给也能投屏，只是极简页和桌面卡片读不到歌名。

### 第 3 步（可选）：开"自动跟随前台应用"

```powershell
adb shell appops set com.ahui.clustercast GET_USAGE_STATS allow
```

然后在界面里勾上"三指左滑自动投当前前台应用"。不授权也能用，只是固定投上次选定的那个应用。

### 第 4 步（可选）：开「dock 全屏沉浸」

这个开关要写系统设置里的 `policy_control`，需要 `WRITE_SECURE_SETTINGS`。
实测这台 ROM 的 `pm grant` 通路是**开着**的（对没声明该权限的包报的是
`has not requested permission`，不是 `Restriction prevents…`），所以授权一次就行、重启不失效：

```powershell
adb shell pm grant com.ahui.clustercast android.permission.WRITE_SECURE_SETTINGS
```

不给也没关系：其他功能照常，只有这个开关按下去会在日志里回一句权限不够。

### 第 5 步（可选）：恢复原车高德

高德 `com.desaysv.jetour.t1n.psmap` 当前是 `enabled:false`（之前被禁过），要恢复：

```powershell
adb shell pm enable com.desaysv.jetour.t1n.psmap
```

### 第 6 步：验证（30 秒）

1. 状态行：**后台服务：运行中 · 仪表屏：已点亮 · 通知使用权：已授予**，并显示当前仪表模式。
2. 真手做**三指左滑** → 日志出现"收到三指手势 300（来源屏 0）"，仪表切极简并出现我们的页面。
   - 日志若写"写极简模式没生效，仪表还停在导航模式"，说明总线不认我们的写入，见第五节。
   - v4.1.4 之前 **代码里没有任何地方启动过 `ClusterActivity`**，所以极简档仪表是一片空；
     现在三指左滑会先把我们那张页铺上 display 2。要验的就是这一屏有没有东西。
3. 主屏随便点几个应用 → 仪表屏**不动**。
4. **三指右滑** → 页面收掉，仪表退回原来的模式。
5. 放一首酷狗的歌 → 主屏桌面那张音乐卡片出现歌名。
6. 点「dock 沉浸」→ 日志回一句"沉浸已开，影响 N 个自装应用（回读一致）"，
   然后切到任意自装应用，底部 dock 应该消失；再点一次应回"沉浸已关"。
   `adb shell settings get global policy_control` 可核对。
7. 点「屏蔽弹窗」→ 日志回"开始盯系统弹窗，出现就顶掉"；等那个"管理员不允许"再弹出来时，
   最多 6~12 秒内应被顶回原应用，日志出"系统弹窗（管理员不允许）已顶掉，回到 xxx"。

## 四、重新构建

需要 JDK、Android SDK（build-tools 34.0.0 + platform android-34），路径在脚本顶部变量里。

```powershell
powershell -ExecutionPolicy Bypass -File build_clustercast.ps1     # 旧 v3（Java 源码）
powershell -ExecutionPolicy Bypass -File v4.1.3\build.ps1          # v4.x（Kotlin 源码）→ ClusterCast-v4.1.4.apk
```

v4.x 这台电脑上没有 kotlinc 可执行文件，`v4.1.3\build.ps1` 直接用 gradle 发行包里的
`kotlin-compiler-embeddable-1.9.20.jar` 跑 `org.jetbrains.kotlin.cli.jvm.K2JVMCompiler`，
再走 aapt2 → R8（kotlin-stdlib 当**程序输入**传进去）→ aapt add → zipalign → apksigner。
2026-09-19 第一次跑通时踩的三个真坑（脚本里已修）：

- **embeddable 编译器不打包 stdlib/trove**：`java -cp` 只放 kotlin-compiler-embeddable 会
  `NoClassDefFoundError: kotlin/jvm/internal/Intrinsics`，补上 stdlib 后又报
  `gnu/trove/THashMap`。启动 classpath 得凑齐
  `kotlin-compiler-embeddable + kotlin-stdlib + trove4j + annotations + kotlin-reflect +
  kotlin-script-runtime + kotlin-daemon-embeddable`（gradle-8.5\lib 下全都有）。
- **PowerShell 会拆 `-Dfile.encoding=UTF-8` 里的点**，java 收到的是 `.encoding=UTF-8` →
  整个参数要加引号 `"-Dfile.encoding=UTF-8"`。
- **`$ErrorActionPreference='Stop'` 下，原生命令的多行 stderr 会变成终止错误**：
  R8 那条几百行的 "The following library types, prefixed by java.…" 警告直接把构建打断。
  调 R8 / kotlinc 时临时降成 `SilentlyContinue`、stderr 重定向到文件，用 `$LASTEXITCODE`
  判成败，失败才把文件前 30 行打出来。

另外这次还改了一处源码里本来就编译不过的写法：`CastService` 的 `mThemeRetry` 在自己的
初始化 lambda 里引用自己，Kotlin 1.9 报 `variable 'mThemeRetry' must be initialized`；
改成 `private val mThemeRetry = Runnable { themeRetry() }` + 成员函数，行为不变。

旧 v3 已知、仍未变的两个坑：
- **aapt2/javac 打不开含中文的目录** → 源码先同步到 `%TEMP%\ccbuild3` 再构建，产物拷回。
- **d8 编不了"捕获了 this 的匿名内部类"**（报 `NullPointerException: <parameter1> is null`）
  → 全项目只用 lambda、方法引用和 `static` 嵌套类 + `WeakReference`。
  `CastService.GestureRx` / `MirrorTick`、`MainActivity.Refresh`、`ClusterActivity.Tick` 都是这么写的，
  加新类时照这个来。字段初始化式里引用自己要用 `this.xxx`，否则 javac 报"初始化代码中引用了自身"。

**CI（不依赖这台电脑）**：`v4.1.3\build_ci.sh` 是 `build.ps1` 的 Linux 等价版，同样把源码同步到
纯 ASCII 临时目录、同样把 kotlin-stdlib 当 R8 的位置参数、跑同样两条 dex 自检
（kotlin 运行时类数 > 100、manifest 里每个 `android:name=".X"` 组件都能在 dex 里找到）。
`.github/workflows/build-apk.yml` 在 push / PR / 手动触发时装 JDK 17 + build-tools 34.0.0 +
platform android-34 + Kotlin 1.9.20 编译器，产出用仓库内 `debug.keystore` 签名的 APK 作为 artifact，
并 `apksigner verify --print-certs` 打印签名指纹 —— 和本地装的包同签名，可以直接覆盖升级。
CI **完全不碰车机**：装上之后的行为验证还得按第三节在车上做。

## 五、已知限制与待办

- **仪表模式写入已经确认落地**（2026-09-19 18:44，v4.2.1 验证包，普通应用 uid 10018）：
  反射 `VDBus.set()` 写 `CMD_ID=232 VALUE=[3]` 后回读 `当前仪表模式：导航模式`，
  日志通道显示走的是 `VDBus+Proxy`，MCU 认。所以这条不再是待办，只剩日常核对：
  连车时顺手开 `adb logcat -s ClusterCast:V ClusterCast.Vd:V VDS-CarInfo-CarInfoService:V`，
  应该同时看到 `onSet ... cmdId = 232` 和随后的 `onGet` 同值回读。
- 仪表屏不可触控，投上去的画面只能在主屏操作（原车高德也一样）。
- 「整屏投应用」模式下，singleTask 应用投到仪表屏后主屏点不开（系统只会把意图投递到那份实例）。
  用默认的极简模式就没这个问题。
- 个别应用不支持在副屏启动（闪退或弹回主屏），属应用自身行为。
- 车机重启后服务由 `BootReceiver` 自动拉起；有用户反馈"重启后要先打开 App 才能投屏"，
  目前还没稳定复现，遇到时先重启车机再看日志。
- **「您的管理员不允许进行这项更改」弹窗（2026-09-19 定位清楚，别再怀疑小黑屋）**
  弹窗本体是 `android/android.accounts.CantAddAccountActivity`，`from uid 1000`，每 **20 秒**来一次
  （22:21:48 / 22:22:08 / 22:22:28 / 22:22:48 实测）。
  发起方是全机唯一的账号认证器 —— 蓝牙电话本
  `com.android.bluetooth/…pbapclient.AuthenticationService`（`/system/app/DsvBluetooth`），
  `dumpsys account` 里全是它 add/remove 账号的循环。
  挡住它的是 **user 0 的基础限制 `no_modify_accounts`**，来源是 ROM 自己的
  `config_defaultFirstUserRestrictions`；`dumpsys user` 里
  `Device policy global restrictions: null`、`local: none`，**跟小黑屋占着 Device Owner 无关**
  （虽然小黑屋确实还在当 DO、`dpm remove-active-admin` 仍报 `Attempt to remove non-test admin`）。
  想命令行清掉也不行：这台 ROM 的 `pm set-user-restriction` 参数解析是坏的，
  任何写法都回 `Error: valid value not specified`。
  → 普通应用点不掉别人的对话框，零特权只能"顶掉"：`AdminGuard` 认出前台包是 `android`
  就把底层应用重新拉回前台，界面上就是「屏蔽弹窗」开关。
  想彻底不出现：配对手机里关掉"联系人共享"。
